# X2Notion

X(旧Twitter)のブックマークを取得し、Notionのデータベースへ一括で登録するCLIツールです。

- Playwrightで自分のログイン状態のままブックマーク画面を読み込み、Xの内部APIレスポンスから本文・画像・投稿日時などを取得します
- ツイートURLをキーに重複判定するため、何度実行しても新規分だけが追加されます

**バージョン: v1.8.2** ｜ 変更履歴は [CHANGELOG.md](CHANGELOG.md) を参照

---

## 1. セットアップ

### 1-1. 依存パッケージのインストール

**セットアップ済みです。** プロジェクト内の `.venv` に Playwright / requests / python-dotenv と Chromium が導入されています。
以降のコマンドは `.venv\Scripts\python.exe` を使ってください（`python` ではなく）。

環境を作り直す場合のみ、以下を実行します。

```bash
python -m venv .venv
```

```bash
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

```bash
.\.venv\Scripts\python.exe -m playwright install chromium
```

### 1-2. Notionコネクトの作成（トークン取得）

Notion APIは「ロボット用のアカウント」を作り、それにトークンを発行して使います。
**旧称は「インテグレーション」ですが、現在のNotion UIでは「コネクト」（英語版は Connections）という名称です。**

1. Notionの左サイドバー下部から **「設定」** を開く
2. **「コネクト」** タブを選ぶ
3. **「自分のコネクトを開発する」**（Develop your own connections）をクリック
4. **「+ 新しいコネクト」** を押し、名前（例: `X2Notion`）とワークスペースを指定して作成
5. 一覧に表示されたコネクト名の横の **「•••」** メニューからトークンをコピー

コピーしたトークン（`ntn_` または `secret_` で始まる文字列）が `NOTION_TOKEN` になります。

> コネクトの作成には**ワークスペースのオーナー権限**が必要です。
> 直接開く場合のURL: https://www.notion.so/my-integrations

### 1-3. 親ページにコネクトを招待

**トークンを持っているだけでは、コネクトはワークスペースを一切参照できません。**
人をページに招待するのと同じように、使いたいページへ明示的に招待する必要があります。

1. データベースを作りたいページを開く
2. 右上の **「•••」** メニューをクリック
3. ポップアップ最下部の **「コネクトを追加」** を選択
4. 1-2で作成したコネクト（例: `X2Notion`）を検索して選択

**この操作をしないとAPIからページが見えず、setupが `Could not find page with ID` で失敗します。**

### 1-4. .env の作成

`.env.example` をコピーして `.env` を作成し、トークンを記入します。

```bash
copy .env.example .env
```

```
NOTION_TOKEN=ntn_xxxxxxxxxxxxxxxxxxxx
NOTION_DATABASE_ID=
```

### 1-5. データベースの作成

親ページのURLをそのまま渡すだけで、必要なプロパティを持つデータベースが自動生成されます。

```bash
.\.venv\Scripts\python.exe -m src.main setup --parent-page https://www.notion.so/xxxxxxxxxxxxxxxxxxxx
```

出力された `NOTION_DATABASE_ID=...` の行を `.env` に貼り付けてください。

## 2. かんたん実行（コマンド不要）

初回設定が済んでいれば、以降はコマンドを打つ必要はありません。

### ダブルクリックで取り込む

エクスプローラーで **`取り込み実行.bat`** をダブルクリックするだけです。
ブラウザは表示されず、進捗が画面に出て、終わると結果が残ります。

取り込みが終わると、**Xのブックマークから削除するか確認を求めます**（`y` で実行）。
削除したくない場合はそのまま Enter を押してください。

### 自動で取り込む（おすすめ）

**`自動実行を設定.bat`** をダブルクリックすると、毎日決まった時刻に自動で取り込むよう
Windowsのタスクスケジューラに登録されます（既定は毎日 21:00）。
これ以降は**操作不要**で、放っておけばNotionに溜まっていきます。
取り込んだブックマークはX側から自動で削除されます（確認は省略されます）。

時刻を変えたい場合はコマンドから指定できます。

```bash
.\.venv\Scripts\python.exe -m src.main schedule --at 08:30
```

| 操作 | 方法 |
|---|---|
| 登録状況の確認 | `.\.venv\Scripts\python.exe -m src.main schedule --status` |
| 解除 | **`自動実行を解除.bat`** をダブルクリック |

自動実行の結果は `logs/` 配下に日付ごとのファイルとして記録されます
（例: `logs/2026-08-08.log`）。うまく取り込めていないときはここを確認してください。

> 自動実行にはCookie方式の設定が必須です。
> Cookie未設定の状態で登録しようとすると、その旨を表示して中断します。

## 3. 使い方（コマンド）

### Xの認証設定（Cookie方式）

**Xは自動操作ブラウザでのログインを制限しています。** ログイン画面で「続ける」を押しても
反応しない場合はこれが原因です。そのため、ログイン操作は自動化せず、
**普段お使いのブラウザのログイン済みセッションを借りる**方式を推奨します。

1. 普段お使いのブラウザでXにログインした状態で **F12**（開発者ツール）を開く
2. **「アプリケーション」**（Application）タブを選ぶ
3. 左メニューの **「Cookie」→ `https://x.com`** をクリック
4. 一覧から **`auth_token`** と **`ct0`** を探し、「値」列をコピー
5. `.env` に貼り付ける

```
X_AUTH_TOKEN=<auth_tokenの値>
X_CT0=<ct0の値>
```

> この2つはログイン情報そのものです。他人に共有しないでください。
> `.env` は `.gitignore` 済みです。Xからログアウトすると無効になるので、
> その場合は取り直してください。

### 複数アカウントを取り込む場合

`accounts.example.json` を `accounts.json` にコピーし、アカウントごとにCookieを記入します。
記入したアカウントを**上から順に連続で取り込みます**。

```json
{
  "accounts": [
    { "label": "メイン", "auth_token": "...", "ct0": "..." },
    { "label": "サブ",   "auth_token": "...", "ct0": "..." }
  ]
}
```

- `label` はNotionの「アカウント」欄に記録される名前です。自由に付けられます
- `accounts.json` があれば `.env` の `X_AUTH_TOKEN` / `X_CT0` より優先されます
- 各アカウントのCookieは、**そのアカウントでログインしたブラウザ**から取得してください
  （ブラウザのプロフィールを分けるか、シークレットウィンドウを使うと取得しやすいです）
- `accounts.json` は `.gitignore` 済みです

既存のデータベースを使っている場合は、「アカウント」プロパティを追加します
（既存の行やプロパティには影響しません）。

```bash
.\.venv\Scripts\python.exe -m src.main migrate
```

### 初回実行

```bash
.\.venv\Scripts\python.exe -m src.main run --limit 10 --dry-run
```

`--dry-run` を付けると、Notionには書き込まずに登録対象の一覧だけを確認できます。

ブラウザは常に非表示で動作します。認証はCookie方式のみで、`X_AUTH_TOKEN` / `X_CT0`
（または `accounts.json`）が未設定のアカウントはスキップされます。

### 本番実行（全件取り込み）

```bash
.\.venv\Scripts\python.exe -m src.main run
```

### 取り込み後にXのブックマークから削除する

```bash
.\.venv\Scripts\python.exe -m src.main run --remove-from-x
```

Xのブックマークを「未処理の受け皿」として使い、Notionへ移したら空にしていく運用向けです。

> **この操作は取り消せません。** Xのブックマークから削除したポストは元に戻せません。

安全のため、以下の制約を設けています。

- **`--remove-from-x` を明示したときだけ**動作します（既定では削除しません）
- **Notionへの保存が確認できた分だけ**削除します。登録に失敗したものは残ります
- 手動実行時は**件数を表示して確認**します（自動実行では確認を省略）
- `--dry-run` と併用すると、削除件数だけを確認できます

```bash
.\.venv\Scripts\python.exe -m src.main run --dry-run --remove-from-x
```

なお削除すると、**Notion側で行を消しても再取得されなくなります**
（Xのブックマークに残っていないため）。この点だけ運用前にご確認ください。

### 差分取り込み（定期実行向け）

```bash
.\.venv\Scripts\python.exe -m src.main run --limit 50
```

各アカウントから新しい50件ずつを取得し、未登録のものだけを追加します。
（3アカウントなら最大150件が対象になります）

## 3. オプション一覧

| コマンド | オプション | 説明 |
|---|---|---|
| `setup` | `--parent-page` | データベースを作る親ページのIDまたはURL（必須） |
| `setup` | `--title` | 作成するデータベース名（既定: `Xブックマーク`） |
| `run` | `--limit N` | **アカウントごとの**取得件数の上限。未指定なら末尾まで取得 |
| `run` | `--dry-run` | Notionに書き込まず、対象一覧のみ表示 |
| `run` | `--log` | 実行内容を `logs/` 配下に記録する |
| `run` | `--remove-from-x` | 保存確認できた分をXのブックマークから削除する（**取り消し不可**） |
| `migrate` | （なし） | 既存DBに不足しているプロパティを追加する |
| `schedule` | `--at HH:MM` | 毎日の自動実行を登録する（既定: 21:00） |
| `schedule` | `--remove` / `--status` | 自動実行の解除 / 登録状況の確認 |
| `properties` | （なし） | 現在のプロパティ対応表を表示する |
| `properties` | `--detect` | 現在のDB構成から対応表を作り直す |

## 4. 作成されるデータベースの構成

| プロパティ | 種類 | 内容 |
|---|---|---|
| タイトル | タイトル | 本文の先頭60文字（超える場合は末尾に `...`） |
| URL | URL | ツイートURL（重複判定のキー） |
| 本文 | テキスト | 全文（t.coリンクは展開済み） |
| 投稿者 | テキスト | 表示名 |
| ユーザーID | テキスト | @ハンドル |
| 投稿日 | 日付 | ツイートの投稿日時 |
| いいね | 数値 | いいね数（取得時点） |
| リポスト | 数値 | リポスト数（取得時点） |
| メディア | ファイル | 添付画像（最大4件） |
| タグ | マルチセレクト | 本文中のハッシュタグ（最大10件） |
| 取込日時 | 日付 | このツールが登録した日時 |
| アカウント | マルチセレクト | このツイートをブックマークしていたXアカウント（複数可） |

ページ本文には、ツイートのブックマークブロック・全文・画像が展開されます。

> タイトルは**行では区切りません**。Xのポストは見栄えのために文の途中で改行する
> ことが多く、1行目だけを採ると断片になるためです。改行は削除して1行に繋げてから
> 60文字で切ります。ただし改行の前後がどちらも半角英数字のときだけは、
> 英単語が連結しないよう空白を残します。
>
> 文字数を変えたい場合は `src/x_bookmarks.py` の `TITLE_MAX_CHARS` を変更し、
> 既存行にも反映するなら次を実行します。
>
> ```bash
> .\.venv\Scripts\python.exe -m tools.rebuild_titles --dry-run
> ```

### プロパティ名を変えた／削除した場合

`properties.json` で、ツール内部の項目とNotionのプロパティ名を対応付けています。
**Notion側で名前を変えたり削除したりした場合は、次のコマンドで対応表を作り直してください。**

```bash
.\.venv\Scripts\python.exe -m src.main properties --detect
```

現在のDB構成を読み取り、対応付けを自動で推定して `properties.json` に保存します。
推定が誤っている場合はファイルを直接編集してください。値を `null` にすると、その項目は書き込みません。

現在の対応表を確認するだけなら、引数なしで実行します。

```bash
.\.venv\Scripts\python.exe -m src.main properties
```

削除したプロパティを戻したい場合は、`properties.json` に名前を書いてから `migrate` を実行します。

> **本文・画像は、プロパティが無くてもページ本文に残ります。** プロパティを削って
> 一覧をすっきりさせても、内容そのものは失われません。

### Notion側で操作してよいこと／いけないこと

**問題ないこと**

| 操作 | 補足 |
|---|---|
| ビューの追加・フィルタ・並べ替え・グループ化 | ビューはAPIに影響しません |
| プロパティの**追加** | ツールは未知のプロパティを無視します |
| 各ページの値の編集、本文の追記 | 次回実行で上書きされることはありません |
| データベース名の変更 | 参照はIDで行うため影響しません |
| プロパティの表示順・列幅の変更 | 表示上の設定のみ |

| プロパティの**名前変更** | `properties --detect` を実行すれば追従します |
| プロパティの**削除** | その項目の書き込みを自動でスキップします（要 `properties --detect`） |

**壊れること**

| 操作 | 何が起きるか |
|---|---|
| プロパティの**型変更** | 自動修復不可。Notion側で型を戻してください |
| **URL** プロパティの削除 | 重複判定ができないため実行を中断します（必須項目） |
| データベースの削除・ゴミ箱移動 | `object_not_found` エラー |
| コネクトの接続解除 | 同上 |
| 接続していない場所へのDB移動 | アクセス権を失いエラーになる場合があります |

名前変更や削除をしたあとに `properties --detect` を実行し忘れた場合も、
実行前の検証で中断し、対処コマンドを案内します（二重登録は起きません）。

### 行を削除した場合

**削除した行は次回実行で再取得されます。** 重複判定はNotionに現存する行のURLと突き合わせる方式で、
削除済み（ゴミ箱を含む）の行はAPIの検索結果に含まれないためです。

Xのブックマーク側から外せば取得対象から消えます。Notion上だけで整理したい場合は、
削除ではなく**チェックボックス等のプロパティを追加してフィルタで隠す**運用をおすすめします。

## 5. 注意事項

- **利用規約**: Xの利用規約は自動化されたアクセスを制限しています。本ツールは自分のアカウントの自分のブックマークを取得する用途を想定していますが、使用は自己責任でお願いします。短時間に何度も実行することは避けてください。
- **Xの仕様変更**: 内部APIのレスポンス構造が変わると取得できなくなる可能性があります。その場合は [`src/x_bookmarks.py`](src/x_bookmarks.py) の解析処理の修正が必要です。
- **取得件数**: Xのブックマークは古い分までスクロールで読み込む必要があるため、件数が多いと時間がかかります。

## 6. トラブルシューティング

| 症状 | 対処 |
|---|---|
| `設定エラー: NOTION_TOKEN が設定されていません` | `.env` を作成し、トークンを記入する |
| setup時に `Could not find page with ID` | 親ページの「•••」→「コネクトを追加」でコネクトを招待する（1-3参照） |
| 設定に「コネクト」タブが無い | ワークスペースのオーナー権限が必要。オーナーに作成を依頼する |
| `Executable doesn't exist` / `BrowserType.launch_persistent_context` | `.\.venv\Scripts\python.exe -m playwright install chromium` を実行する |
| ログイン画面で「続ける」が反応しない | Xの自動操作制限。Cookie方式（1-6参照）に切り替える |
| `Xのログイン状態を確立できませんでした` | Cookieが期限切れ。`auth_token` / `ct0` を取り直す |
| `ブックマークが1件も取得できませんでした` | Cookieが期限切れの可能性。`auth_token` / `ct0` を取り直す |
| 途中で取得が止まる | `scroll_pause_ms` を大きくする（`src/x_bookmarks.py`） |

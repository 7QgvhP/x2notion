# 0001. ADR で設計判断を記録する

- ステータス: Accepted
- 日付: 2026-11-15

## 背景（Context）

設計判断の理由が、README、CHANGELOG（Git 管理以前の経緯）、ソースのコメントに分散しており、判断の単位で参照できなかった。

## 決定内容（Decision）

重要な設計判断を、`docs/adr/` に ADR として1判断1ファイルで記録する。

## 理由と検討した代替案（Consequences / Alternatives）

- 判断の背景と理由が残り、後から変更するときの判断材料になる。
- 代替案: README や CHANGELOG に書き続ける → 判断の単位で参照・置き換えができないため採用しない。

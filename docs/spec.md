# 仕様

## 目的とスコープ

自分の X アカウントのブックマークを、Notion のデータベースに取り込む。

### やること
- X のブックマークを取得し、Notion のデータベースに1ポスト1行で登録する。
- 複数のアカウントを、記載順に続けて取り込む。
- 指定したときだけ、取り込んだポストを X のブックマークから削除する。
- 毎日の自動実行を、Windows のタスクスケジューラに登録する。

### やらないこと
- X へのログイン操作（Cookie 方式のみ。[ADR 0002](adr/0002-cookie-auth-only.md)）。
- Notion で削除した行の記録（削除した行は、次回の実行で再取得される）。
- 他人のブックマークや、ブックマーク以外のポストの取得。

## 機能一覧

### データベースの作成（`setup`）
親ページの ID または URL を受け取り、その下に、下記の構成のデータベースを作る（既定の名前は「Xブックマーク」）。作成したデータベースの ID を表示する。

### 取り込み（`run`）
次の順に処理する。

1. Notion の登録済みデータを確認する（プロパティの構成の検証を含む）。
2. 各アカウントの X のブックマークを取得する（`--limit` で、アカウントごとの件数の上限を指定できる）。
3. Notion へ反映する。未登録のポストは行を追加し、登録済みのポストを別のアカウントでもブックマークしていた場合は「アカウント」に追記する。
4. `--remove-from-x` を指定したときだけ、X のブックマークから削除する。

- `--dry-run` を付けると、Notion にも X にも書き込まず、対象の一覧（と削除する件数）だけを表示する。
- `--log` を付けると、実行内容を `logs/<日付>.log` に追記する。

### X のブックマークからの削除（`run --remove-from-x`）
取り消せない操作のため、次の制約を設けている。

- `--remove-from-x` を明示したときだけ動く（既定では削除しない）。
- Notion への保存を確認できた分だけを削除する。登録に失敗したものは残る。
- 手動実行のときは、件数を表示して確認を求める。自動実行（`scheduled_run.bat`）では確認を省略する。

削除すると、Notion 側で行を消しても再取得されなくなる。

### 重複の判定
ツイート ID（URL の `status/<数字>`）を鍵にする（[ADR 0004](adr/0004-dedupe-by-tweet-id.md)）。ID を取り出せない URL だけは、`twitter.com` / `x.com` の表記ゆれとクエリ文字列を吸収した URL で比較する。
Notion に現存する行（ゴミ箱を除く）の URL と突き合わせるため、Notion で削除した行は、次回の実行で再取得される。

### プロパティの追加（`migrate`）
既存のデータベースに、足りないプロパティ（例: 「アカウント」）を追加する。既存の行やプロパティには影響しない。

### プロパティの対応表（`properties`）
- 引数なし: 現在の対応表（`properties.json`）を表示する。
- `--detect`: 現在のデータベースの構成を読み取り、対応付けを推定して `properties.json` に保存する。

### 自動実行（`schedule`）
- `--at HH:MM`（既定 21:00）で、毎日その時刻に `scripts/scheduled_run.bat` を実行するタスク（`X2Notion_Bookmarks`）を登録する。同名のタスクがあれば上書きする。
- `--remove` で解除、`--status` で登録状況を表示する。
- 自動実行は `run --log --remove-from-x` を、コンソールなし（`pythonw.exe`）で実行する。Cookie が未設定のときは、登録せずに中断する。

### タイトルの作り直し（`tools.rebuild_titles`）
既存の行のタイトルを、現在のタイトルの規則で作り直す。`--dry-run` で、変更内容だけを表示する。

## 入出力とデータ形式

### 入力
- X のブックマーク（`https://x.com/i/bookmarks` の表示時に、X の内部 API が返す応答）。
- 設定: `.env`、`accounts.json`、`properties.json`（[configuration.md](configuration.md)）。

### 作成されるデータベースの構成

| プロパティ | 種類 | 内容 |
|---|---|---|
| タイトル | タイトル | 本文の先頭60文字（超える場合は末尾に `...`） |
| URL | URL | ツイートの URL（重複判定に使う。必須） |
| 本文 | テキスト | 全文（t.co のリンクは展開済み） |
| 投稿者 | テキスト | 表示名 |
| ユーザーID | テキスト | @ハンドル |
| 投稿日 | 日付 | ツイートの投稿日時 |
| いいね | 数値 | いいね数（取得時点） |
| リポスト | 数値 | リポスト数（取得時点） |
| メディア | ファイル | 添付画像（最大4件） |
| タグ | マルチセレクト | 本文中のハッシュタグ（最大10件） |
| 取込日時 | 日付 | このツールが登録した日時 |
| アカウント | マルチセレクト | このポストをブックマークしていた X アカウント（複数可） |

- 実際に書き込むプロパティ名は、`properties.json` の対応表に従う。値が `null` の項目は書き込まない。
- ページ本文には、ツイートのブックマークブロック、全文、画像（最大4件）を展開する。プロパティを削っても、本文と画像はページ本文に残る。

### タイトルの規則
- 行では区切らない。改行は削除して1行に繋げてから、60文字（`TITLE_MAX_CHARS`）で切る。X のポストは見栄えのために文の途中で改行することが多く、1行目だけを採ると断片になるため。
- 改行の前後がどちらも半角英数字のときだけ、英単語が連結しないよう空白を残す。
- 本文がない場合は「(本文なし)」。

## 制約条件

- X の利用規約は、自動化されたアクセスを制限している。自分のアカウントの自分のブックマークを取得する用途を想定しており、短時間に何度も実行しない。
- X の内部 API の応答の構造が変わると、取得できなくなる可能性がある。
- ブックマークは古い分までスクロールで読み込むため、件数が多いと時間がかかる。
- Notion API は、リクエストの間に 0.35 秒の間隔を空け、429（レート制限）のときは `Retry-After` に従って再試行する。

## エラー時の挙動

| 状況 | 挙動 |
|---|---|
| `NOTION_TOKEN` がない、`accounts.json` の書式が不正など | 「設定エラー: …」を表示して終了する |
| Notion のプロパティの構成が対応表と合わない | 実行前の検証で中断し、対処のコマンド（`properties --detect` など）を案内する（二重登録は起きない） |
| URL のプロパティがない | 重複判定ができないため中断する |
| Cookie が未設定のアカウント | そのアカウントをスキップする |
| Cookie が期限切れ | 「Xのログイン状態を確立できませんでした」、または「ブックマークが1件も取得できませんでした」と表示する |
| Notion への登録に失敗したポスト | X のブックマークから削除しない |

対処の手順は [usage.md](usage.md#よくあるエラーと対処) を参照。
